# Recovery effects and dash/jump input buffer

Updated: 2026-10-08.

Healing and revival use the existing authored sprite frames and timings on the Game HUD overlay Canvas. The sprites render in front of the body and follow it after the camera update. The old notification borders and labels are disabled, the image offset is zero, simultaneous effects share the body anchor, and screen-edge clamping is removed. Facing left does not mirror the effects. `StatueRecoverySceneSetup.ConfigureEffect` retains this layout when reauthoring the HUD.

The user subsequently requested larger effects: both now use a 117 × 117 maximum image size, increased by 50% from 78 × 78, preserving relative frame sizes and the body anchor. The shared HUD prefab and component default are updated. Unity compilation and the targeted prefab diff were checked; this size-only follow-up did not rerun the gameplay tests below. Before copies: `outputs/recovery-size-20261008`.

The latest follow-up replaces fixed pixel sizing with coverage based on the projected neutral player sprite. That sprite's local bounds are cached when binding the player, keeping the anchor and size stable during wide skill animations. Four projected corners determine body size in Canvas coordinates, following player scale, facing and camera zoom. `healBodyScale = 4` gives the main healing ring a diameter about 1.2 times the body height; `reviveBodyScale = 2.2` makes the bright revival beam cover the full body. Authored frame proportions and timing remain intact. The previous 117 × 117 setting remains a fallback when no body sprite is available.

`Health.OnShieldBroken` fires once when damage reduces a live shield to zero. Partial hits, invulnerability and natural expiry do not emit it. `PlayerConsumables` reuses the existing Shield Effect Animator's `Base Layer.Break` state and 0.683-second clip, enabling the object before querying Animator state availability. It hides the effect after one scaled clip duration, despite the authored clip being marked looping. A fresh shield cancels the break and returns to the existing `Shiled` state; disable/death clean up the presentation and subscriptions. Shield HP, overflow damage, item costs and the existing expiry rules are unchanged. No AnimatorController or clip was edited.

Latest validation: Unity compilation succeeded; all 32 focused Play Mode checks passed for shielding events/damage/lifetime/pause/reuse, recovery coverage/zoom/facing, and size stability with the real Skill3 sprite. Game-view screenshots show the main healing ring around the body, the bright revival column hiding it, and the authored shield break pose. During an intermediate Play Mode transition the open Sprite Editor attempted to apply Attack1 sprite edits and left an asset-editing lock after an Editor exception; the lock was balanced, importer state was preserved, and import resumed outside Play Mode. Attack1 metadata matches the recovery snapshot. Intermediate reports and Editor diagnostics are retained. The pause fixture was also corrected to sample after the current animation frame had completed. The final runtime report records no errors. Evidence: `outputs/recovery-coverage-shield-break-20261008`. No standalone build or human keyboard playtest was run for this follow-up.

`PlayerMotor2D` now buffers dash presses for 0.18 seconds, and the existing jump buffer increases from 0.12 to 0.18 seconds. Both values are serialized on the Player prefab and editable in the Inspector. Dash requests wait for action completion, dash completion/cooldown, an available air charge, or sufficient stamina, while the buffer remains valid. Stamina is spent only when the dash begins. `PlayerController` retries the dash after combat has released control, allowing a same-frame skill-to-dash handoff. Jump still requires ground support or existing coyote time; no extra air jump is added. Each pending input expires or is consumed once, and knockback, death/revival, panel suspension, pause, and disabling the controller clear it.

Two additional lifecycle checks passed for the controller's automatic pause path and disable cleanup. Game-view screenshots verified both effects over the torso.
